# Spec（Phase 1 - Requirements）：树园的工具导航（首期：文本比对 MVP）

> 版本：v0.1（需求对齐稿）
>  
> 说明：本需求文档聚焦“单页应用 + 第一个工具：文本比对”。整体视觉参考 Apple 官网：**浅色极简 + 高级排版 + 克制动效**。

## 1. 目标（Objective）

为个人打造一个网页「树园的工具导航」，把常用工具聚合在一个页面里。首期（MVP）先交付一个可用、好看、可部署到云端的单页网站，其中核心工具为“文本比对”。

### 成功标准（Success）
- 打开网页即可使用文本比对，不需要登录。
- 文本比对能**高亮**展示差异，并支持快速跳转差异。
- 页面应展示“差异数量”统计：无差异为 0；有差异时显示差异条目数。
- 提供“一键清空空行”能力，解决复制粘贴带来的多余空行问题。
- 页面风格具有“苹果风”：简约但有设计感（排版、间距、层级、微动效）。
- 默认**纯前端本地比对**：文本不上传服务器（适配敏感文本场景）。

## 2. 用户与场景（Users & Scenarios）

### 目标用户
- 你自己（个人使用、编程新手，但希望交付质量高、体验好）

### 典型场景
- 对比两段文案/合同条款/配置片段，找出修改点。
- 从聊天/文档复制文本，包含很多空行，需要快速清理再对比。
- 较频繁使用，希望页面打开快、操作少。

## 3. 范围（Scope）

### 本期包含（In Scope）
1. 单页：Header（标题/简介） + 工具区（文本比对工作台） + Footer（可选）。
2. 文本比对 MVP：
   - 左侧输入「原文本」、右侧输入「对比文本」（均可编辑）
   - 点击比对后展示差异结果（高亮新增/删除/修改）
   - 差异导航：上一处 / 下一处
   - 工具按钮：清空、左右互换、**一键清空空行**
   - 本地处理（无后端依赖）
3. 视觉与交互：
   - 浅色极简、排版讲究、间距统一
   - 微动效（hover/press/淡入），但保持克制
   - 响应式：桌面双栏，窄屏（手机）上下布局

### 本期不包含（Out of Scope）
- 用户系统/登录/保存历史 diff/云端同步
- 多文件格式（Word/PDF）解析
- Git diff / patch 输出
- 协作分享链接

## 4. 功能需求（Functional Requirements, EARS）

### 4.1 页面与导航（单页承载）
- **Ubiquitous**：系统应在页面顶部展示产品名「树园的工具导航」与一句简短说明（例如“文本本地比对，不上传服务器”）。
- **Ubiquitous**：系统应在同一页面中提供“文本比对”工作台区域，无需跳转新页面。
- **Optional**：系统可提供“更多工具（Coming soon）”占位区，用于未来扩展。

### 4.2 文本输入与编辑
- **Ubiquitous**：系统应提供两个可编辑文本区域：
  - 左：原文本（Original）
  - 右：对比文本（Changed）
- **Ubiquitous**：系统应支持粘贴与键盘输入编辑。
- **Ubiquitous**：系统应提供「左右互换」功能，一键交换两侧内容。
- **Ubiquitous**：系统应提供「清空」功能，可分别清空或同时清空（具体交互由设计阶段确定）。

### 4.3 一键清空空行（你新增的核心需求）
- **When** 用户点击「一键清空空行」时，系统应对指定侧（或两侧，待确认）文本执行清理：
  - 删除“完全为空”的行（只包含换行符的行）
  - 对“只包含空格/制表符”的行视为“空行”并删除（默认开启）
  - 其他内容保持不变
- **Ubiquitous**：系统应在执行后保持光标与滚动位置尽量稳定（可接受轻微变化）。

> 注：清空空行的范围需要二选一（设计阶段确认）：
> 1) 仅清理当前聚焦的那一侧；2) 一键清理两侧。

### 4.4 本地比对与差异展示
- **Constraint（隐私）**：系统应在浏览器本地完成差异计算，不上传文本至服务器。
- **When** 用户点击「开始比对」时，系统应：
  1) 校验输入合法性（至少一侧非空；更严格规则待确认）
  2) 生成差异结果视图
  3) 用颜色/标记区分新增、删除、修改
- **Ubiquitous**：系统应提供“差异导航”：上一处差异 / 下一处差异。
- **Ubiquitous**：系统应展示“差异数量”统计（count）：
  - 若两侧内容完全一致，count = 0
  - 若存在差异，count = 差异条目数（以“差异行”或“差异块”为单位，具体单位在实现阶段固定并保持一致）
- **Ubiquitous**：系统应支持左右联动滚动（同步滚动），以便对齐查看（实现细节在设计阶段确认）。

### 4.5 差异粒度（已确认：首期按行）
- **Constraint**：首期差异高亮粒度按“行级”实现，保证稳定与可读。
- **Optional**：后续版本可增加“词/字符级高亮”作为增强能力。

## 5. 非功能需求（NFR）

### 5.1 视觉与体验（苹果风）
- 版式：大标题 + 清晰层级（标题/说明/操作/内容）
- 留白：统一的 8pt/4pt 间距体系（例如 8/16/24/32）
- 字体：优先系统字体栈（Apple 风格的无衬线），强调字重与字号层级
- 色彩：浅色背景（接近 #F5F5F7 的轻灰）+ 少量强调色（蓝/青灰）+ 细分割线
- 动效：按钮 hover、区域淡入、滚动时轻微视差（可选），避免过度炫技导致分心

### 5.2 性能
- 首屏可交互时间尽量短（MVP 以“体感不卡”为验收）
- 对于超长文本：
  - 允许设定上限并提示（例如超过 N 行给出提示）
  - 避免页面卡死（必要时降级：仅提示差异数量/分块渲染）

### 5.3 兼容性
- 现代浏览器（Chrome / Safari / Edge 最新两版）
- 移动端：输入区上下排列；核心操作可完成

## 6. 边缘情况与异常处理（Edge Cases）
- 两侧都为空：提示“请输入文本再比对”
- 一侧为空：允许比对（结果表现为全新增/全删除）或提示（待确认）
- 只有空白差异：结果可能很多但意义不大；后续可加“忽略空白”开关（非 MVP）
- 文本包含超长行：展示可横向滚动，避免破版
- 用户连续点击“开始比对”：应去抖/锁定按钮，避免重复计算导致卡顿

## 7. 验收标准（Acceptance Criteria）
- [ ] 页面标题与说明清晰，整体风格浅色极简且有设计感
- [ ] 左右文本可编辑；可清空、可互换
- [ ] 点击开始比对可看到行级差异高亮，且差异能明显区分新增/删除/修改
- [ ] 页面显示差异数量统计：无差异显示 0；有差异显示对应数量
- [ ] 支持上一处/下一处差异跳转
- [ ] “一键清空空行”可有效去除多余空行（含仅空格行）
- [ ] 全程本地计算，不依赖后端接口
- [ ] 移动端可用（布局自动上下排列）

## 8. 未决问题（Open Questions）
1. 「一键清空空行」默认作用范围：两侧同时清理，还是只清理当前聚焦的一侧？
2. “一侧为空”时的期望行为：允许比对并给出全增/全删结果，还是提示用户补全？
3. 是否需要“复制结果”（复制带标记的纯文本）？MVP 可先不做。
